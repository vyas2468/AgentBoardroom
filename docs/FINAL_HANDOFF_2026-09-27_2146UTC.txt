6. BACKTEST (HISTORICAL REPLAY) - THE TERMINAL SIDE (version 141): a new layer, v104.js, adds
   a "Backtest this portfolio" section to the Portfolio Tracker tab. Given a merged historical
   scan CSV (part F's output) and a price-history CSV, it replays a tracked portfolio's exact
   frozen rules on every date it's eligible to rebalance (respecting that portfolio's OWN
   rebalance-rhythm setting from step 2), using ONLY data that existed on that date, and feeds
   the resulting historical picks through the SAME engine that drives live tracking.
   HOW IT REUSES YOUR OWN CODE (not a reimplementation): it found and reused `upParseCSV`, the
   exact function your page's own "Update" button already uses to read a scan CSV, and
   `hxParseCsv`, the same one "Load price history" uses - substituting them into the page's
   shared global state for one computation, then restoring the original state afterward,
   wrapped in try/finally so an error mid-replay can never corrupt what's currently loaded.
   TESTED (28 new checks, plus the existing 40 tracker checks, all re-verified by me
   independently before publishing, not just taken on trust):
    - Proven identical to the real ingest path, field by field, on your real sample data.
    - No-look-ahead: a full run and the same run with later dates deleted give byte-identical
      results for every date they share.
    - Restore-on-error: forcing a crash mid-replay (twice, two different ways) leaves the live
      scan and price history completely unchanged afterward.
    - A real entry/exit/re-entry case on synthetic data matches hand-computed expectations.
   HONEST ABOUT ITS LIMITS: if a portfolio's rules need correlation/cluster diversification
   (Hidden Groups, price clusters - the "low correlation", "1 per cluster" kind of rule) and
   there isn't enough price history before the first backtest date (252 bars needed), it REFUSES
   with a clear explanation rather than quietly producing a wrong number. Plain filter/rank
   portfolios (uptrend, pullback, improving, momentum, dual momentum, sector/subsector
   conditions) have no such limit - they read straight from each date's own scan data.
   Full 348-question regression: unchanged. 40 tracker tests + 28 new backtest tests: all pass.
