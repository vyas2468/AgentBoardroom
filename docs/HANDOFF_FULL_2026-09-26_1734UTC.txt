## NEXT TASK (start here in the new session): "Tracked lists" - daily buy / sell / hold and performance

### The owner's request (their words, summarised)
Each day, get the terminal to give a final list of tickers from a saved combination question, use it as a research tool
for real orders, and track how it performs: names that drop off the list are sold, new names are bought, names that
remain are held.

### The answer given at the end of the last session (verbatim)
Partly. You can already get a daily list: save the question in My tiles, load the new scan and part E each day, and
press Run. With the same data the same question always gives the same list, so any change comes from the new day's
data. What the terminal doesn't do yet is the bookkeeping you describe.

What's missing today:
1. It doesn't remember yesterday's list. Each answer stands alone, so you'd have to compare the lists by eye to see
   what's new and what dropped out.
2. There's no buy / sell / hold view. Your logic is right: names that drop out are sells, new names are buys, and names
   still on the list are holds. But nothing works that out for you.
3. There's no performance record. Nothing stores the entry date and price, or compares later prices with RSP, so you
   can't see how the list has done over time.

What I'd add (a "Tracked lists" feature, built the same safe way as before):
- Mark a question as tracked: mark any My tiles question as tracked. Each day you press Run, or "Run all tracked" in
  one go.
- Snapshots: each run saves the tickers, the scan date and each name's closing price to your account, like My tiles.
- Changes table: a colour-coded table of BUY (new), SELL (dropped) and HOLD (kept), with the reason each name entered or
  left, e.g. "no longer improving" or "fell out of the top 10".
- A buffer rule against churn: without one, a name at rank 10 today and 11 tomorrow gets sold and bought back, which
  costs money in real trading. The usual fix: keep holding until a name falls below, say, rank 15, and only buy names in
  the top 10. Optionally, add a minimum holding period.
- A performance ledger: each position's entry date and price, its current price and return, the list's equal-weight
  return against RSP, and closed trades with their results. It's all computed from the scan prices you load each day.

Limits to keep in mind:
- The scan is end-of-day, so any real order would fill at the next day's prices. The ledger would show that, so it
  doesn't flatter results.
- The ledger tracks the list itself, not your broker fills. If you want your actual fills, it would need your own entry
  prices typed in.
- It's a way to track results going forward, not a backtest. The terminal can't replay past days, because it only keeps
  the scans you've saved.

Cost: this is one new layer plus tests, a similar size to My tiles (roughly 1.5-2x that work). It's best done in a
fresh session.

## FUTURE TASK 2 (bigger, builds on "Tracked lists"): Portfolio Tracker tab + RealTest backtests

### The owner's request
Create the adaptive / mixed / long-short / block portfolios, track several of them at once (in their own tab), see when
names drop off (sold), stay (held) or join (bought), choose holding-period rules, and assess whether each portfolio is
worth following - including a proper backtest in RealTest (RT), not only forward tracking.

### Why two parts (forward tracking in the page, backtesting in RT)
- The page only holds the scan for the latest bar (plus saved runs) and part E prices. Most portfolio conditions
  (Early Warning direction, severity, convergence lenses, graph anomaly, clusters) are computed by RealTest for one bar,
  so the page cannot recompute them for past days. It can track forward from today, honestly, day by day.
- RealTest computes those same formulas on every historical bar, so a true backtest (entries, exits, holding periods,
  costs) belongs in RT. The page can generate the RT strategy script from a tracked portfolio's rules.

### Part A - Portfolio Tracker tab (in the page, forward tracking)
1. New tab "Portfolio Tracker" (group: Baskets or Reference & AI) built by a new layer (v101), plus a "Track this
   portfolio" button on every portfolio answer (hsmart, mixed, long/short, block / cluster portfolios, risk-level
   portfolios) and on My tiles questions.
2. Tracked portfolio = {id, name, question text, spec kind, settings, created date}. Stored in the account store
   (db) like My tiles: `tracker/<id>` for the definition and `tracker/<id>/days/<YYYY-MM-DD>` for daily snapshots.
3. Settings per tracked portfolio (toggles in the tab):
   - Rebalance: daily / weekly (Mondays) / monthly (first scan of the month) / manual.
   - Holding period: none, minimum N days before a sell is allowed, or fixed N days then re-check.
   - Buffer (churn control): buy only ranks <= N, keep holding until rank > N + B.
   - Exit rule on drop-off: sell when the name leaves the list (default), or only when a named condition fails
     (e.g. "no longer improving", "trend turns down"), or a stop (e.g. -8% from entry) / time exit.
   - Weights: as the answer (equal / inverse volatility / score-rank), fixed amount per name, or notional (e.g. 100k).
   - Small follow-up: in mixed portfolios, state that signal convergence applies to stocks only and show the ETF part's
     "How your question was read" table too.
   - Entry price convention: scan close (reference) and "next open" note; optional manual fill prices.
4. Daily run: "Update all tracked" re-runs every tracked question on the newly loaded scan, applies the settings and
   stores the snapshot (re-running on the same scan date replaces that day).
5. Tab views:
   - Overview table: one row per tracked portfolio - start date, days, holdings, return since start, return vs RSP,
     max drawdown, hit rate, turnover, current status (up / down today).
   - Per portfolio: today's BUY / SELL / HOLD table with reasons; holdings with entry date / price, days held, return;
     closed trades (entry, exit, days, return, why it left); equity curve vs RSP (SVG chart, PNG export); monthly
     returns table.
   - Compare: two or more tracked portfolios on one chart and one stats table.
   - CSV export of trades and the equity curve.
6. Honesty rules shown on the tab: forward tracking only from the first snapshot; returns use scan closes; gaps when a
   day's scan was not loaded are marked, not filled.

### Part B - Backtest in RealTest (the proper test)
1. "Export to RealTest" button on a tracked portfolio: generates an .rts strategy file from its rules:
   - Data: same shared .rtd as the daily workflow (import once); universe = the scan's list.
   - EntrySetup = the portfolio's conditions translated to RT formulas (improving = the Early Warning direction
     formula; uptrend / fresh / established = the trend-filter length; strengthening = severity > 0; not extended =
     ATR distance < 1; signal convergence = the six lens tests summed >= 3; liquidity / volatility percentiles via
     cross-sectional ranks; 52-week high, drawdown, beta from price).
   - SetupScore = the adaptive score (weights from the question) so RT ranks candidates the same way.
   - MaxPositions = N; rebalance timing; ExitRule = not(EntrySetup) or rank > N + buffer; MinHold / ExitTime for the
     holding-period toggle; optional stop.
   - Long / short: two strategies (longs and shorts) in one test; mixed ETFs + stocks: two strategies with their
     allocations.
   - Costs: commission and slippage settings; entries at next open.
2. Map every page condition to its RT source first (a table in the handoff): which come straight from the part A / B /
   C formulas (can be backtested exactly), which need an approximation (graph anomaly, Hidden Groups and price clusters
   are heavy engines - either precompute per bar in a part D-style script or drop them from backtests and say so).
3. Launcher like part E: a .bat + .ps1 that runs the generated .rts with -apply -scan/-test on the shared .rtd, checks
   the logs, and writes a results CSV (trades + daily equity) that the Tracker tab can load and show beside the
   forward-tracking results ("backtest" vs "live since <date>").
4. Validate: run one simple portfolio (e.g. "10 improving stocks in an uptrend") in RT and in the page on the same
   date; the RT entry list for the last bar must equal the page's list. Only then trust the backtest numbers.

### Suggested order across sessions
1. Session 1: "Tracked lists" (the plan above) = snapshots, BUY / SELL / HOLD, buffer, ledger.
2. Session 2: Portfolio Tracker tab (multiple portfolios, settings toggles, overview, compare, equity curves, CSV).
3. Session 3: RT condition mapping table + "Export to RealTest" for the simple conditions; validate the last-bar list.
4. Session 4: holding-period / stop / buffer rules in RT, long-short and mixed strategies, results CSV back into the tab.
Each session: follow the sector-terminal skill (build, full regression unchanged, publish, commit, update handoff).
