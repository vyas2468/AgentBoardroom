PART 3. HOW THE REALTEST SCRIPTS AND THE .BAT FILES WORK - IN SIMPLE ENGLISH
----------------------------------------------------------------------------

3.1 The big picture
   RealTest is the engine that reads market data and calculates things. The terminal page never talks to
   RealTest directly: RealTest writes CSV files (plain tables), and the page reads those files. So the daily job
   is "get RealTest to produce the right tables, check them, and hand them to the page".

   Doing everything in one giant RealTest script would be slow and fragile, so the work is split into parts,
   each a separate .rts script that produces its own CSV:

     Part C  - "engine-free" columns (prices, trends, bands, clusters ...)            about 6 minutes
     Part B  - the correlation family (who moves with whom)                          about 1 minute
     Part A  - the heavy engines (the long one)                                       about 26 minutes
     Part D  - optional engine diagnostics (only with -IncludeD)
     Part E  - the optional price history for Ask the terminal (new today)            under a minute

3.2 The shared data file: why only part C "imports"
   Every part needs the same market data. Downloading it several times would be slow and could give each part
   slightly different data. So:
     - Part C runs with  -import -apply -scan : it downloads the data (import), saves it into one shared data
       file (C:\RealTest21_newerv2\Data\alexaligned_unified_v7.rtd), then calculates (apply) and writes its
       table (scan).
     - Parts B, A, D and E run with  -apply -scan  only: they open that same saved data file and calculate from
       it. They never download. That is why every part sees exactly the same bars and the same symbols.
   The three switches, simply:  import = fetch data;  apply = work out the formulas;  scan = write the table.

3.3 What "scan" means and why the rows line up
   A scan asks RealTest: "for each symbol, write one row with these columns". Parts A, B and C use
   NumBars 1, which means "just the latest bar", so each writes one row per symbol for the same date, all
   from the same data file. Because every part has the same symbols on the same date, their tables line up
   row for row, and can be joined side by side.

3.4 The daily launcher: Run_AlexAligned_v7_Workflow.bat -> run_v7_workflow.ps1
   The .bat file is only a doorway: double-clicking it starts PowerShell and runs run_v7_workflow.ps1, which
   does the real work, step by step, and stops at the first problem:
     1. Preflight: is RealTest already open? (Two RealTest jobs at once would fight over the data file, and an
        open window blocks -import.) Are all the scripts present?
     2. Runs part C, then B, then A (then D if asked), strictly one after the other, waiting for each to finish.
     3. After each part it checks three things:
          - RealTest's batchlog.txt says "OK" for import / apply / scan of that script;
          - errorlog.txt did not get new error lines;
          - a fresh CSV was written (newer than the start of that part) and it has rows.
        If any check fails, it stops and tells you which part and why.
     4. Merge: merge_v7_scans.py joins the part CSVs side by side into one file,
        AlexAligned_Unified_v7_scan.csv (one row per symbol, all 480 columns). It refuses if the parts
        disagree on rows or columns, so a half-finished part can never sneak into the merged file.
     5. Terminal gate: terminal_payload_v7.js reads the merged CSV exactly the way the page will and builds the
        payload the page loads. If the page could not read it, the gate fails and you are told not to load it.
     6. It records the run in v7_last_run.json and tells you the next step: load the merged scan in the terminal
        (Update or the newer-scan banner), then Save this run.

3.5 Part E (new today): Run_AlexAligned_v7_History.bat -> run_v7_history.ps1
   Part E is a copy of part C's setup that asks for history instead of today only:
     - It is run with -apply -scan only (no import), so it reads the SAME shared data file the daily
       workflow just used. That is why it must run after the daily workflow (or at least after part C).
     - It uses NumBars 280, which means "give me the last 280 bars", and writes one row per symbol per day:
       Date, Symbol, Open, High, Low, Close. That is about 575 x 280 = 161,000 rows.
     - It writes its OWN file, AlexAligned_Unified_v7E_history.csv. It is never merged with A, B, C or D, so the
       merge and the terminal gate are not affected at all. The daily workflow does not need it.
   The launcher does the same kind of safety checks as the daily one:
     - the .bat checks the three files (.bat, .ps1, .rts) are together in the Scripts folder, then starts the .ps1
       and always pauses at the end so the window never flashes and disappears;
     - the .ps1 refuses to start if RealTest is running (and shows which process), checks RealTest, the script and
       the shared data file exist, runs RealTest with -apply -scan, then checks batchlog OK lines, no new error
       lines, a fresh CSV, the right header, and at least 20,000 rows. Then it prints "PART E PASSED".

3.6 How the page uses each file
   - The merged scan (AlexAligned_Unified_v7_scan.csv): the page's main data. Every tab reads it. It is one
     row per symbol for the latest bar.
   - The history (AlexAligned_Unified_v7E_history.csv): loaded in Ask the terminal with "Load price history".
     The page stores it and uses it for everything that needs more than one day: returns over months, drawdowns,
     correlations, the clusters map, pair tests, charts.
   - The two files are independent. If the history is older than the scan, the page says so in its notes; the
     fix is simply to run part E again after the daily workflow.

3.7 Your daily routine, in order
   1. Double-click Run_AlexAligned_v7_Workflow.bat and wait for it to finish (about 35 minutes).
   2. Double-click Run_AlexAligned_v7_History.bat (under a minute) and wait for "PART E PASSED".
   3. In the terminal: load the new scan (Update), then Ask the terminal -> Load price history
      -> Scripts\AlexAligned_Unified_v7E_history.csv.
   4. Save this run. Start with the Guide tab or the example tiles in Ask the terminal.

   If a launcher stops, read its last lines: they say which check failed. The most common one is "RealTest is
   already running": close RealTest (or wait for the other job to finish) and double-click again.
