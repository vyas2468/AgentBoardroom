PART A. THE FULL SESSION, START TO FINISH -- WHAT WAS ACCOMPLISHED
----------------------------------------------------------------------------
This was a long session. Here is everything that shipped, in the order it happened:

1. BACKTEST FEATURES (published as v143):
   - "Anomaly leader pages" tile in Ask the terminal -- a structured, multi-table answer layout
     (matching a competitor terminal's style you showed us) for combined-anomaly-score questions,
     with 10 ready-to-run example questions.
   - Backtest is ~47.5x faster (price history parsed once instead of re-parsed on every replay
     date). No visible change to how you use it -- it just finishes faster now.
   - New "Export weights only (fast)" button -- gets Terminal_Weights.csv without running the
     full trade/stats simulation, for when you only want the CSV.
   - Fixed a real bug: "Download Terminal_Weights.csv" was silently doing nothing when clicked.

2. REALTEST WORKFLOW DIAGRAM (published as v144):
   - New "How this connects to RealTest" collapsible panel in the Backtest section, with a
     visual 6-step diagram of the export-to-RealTest-and-back workflow.

3. THE REALTEST CROSS-CHECK -- 3 real runs, a real bug found and fixed:
   - Run 1: RealTest rejected the script outright ("Dynamic-sizing strategy cannot specify
     Side"). One-line fix (side is inferred from the position-size formula's sign, not a
     separate setting, for this kind of strategy).
   - Run 2: RealTest ran, but its return (+8.53%) was way below the terminal's own (+16.56%),
     with almost double the trade count (1,904 vs 964). Investigated by reading RealTest's
     actual trade-by-trade output: RealTest was splitting single holding periods into several
     artificial small trades every time the target position size shifted even slightly day to
     day, and charging its cost assumption on every extra one. Root cause: the exported weights
     file re-states a target weight for a held stock on EVERY day it's held, but the terminal's
     own engine never actually resizes a position once bought. RealTest was doing exactly what
     it was told -- the instruction just didn't match the terminal's real behaviour.
   - THE FIX: added "if you already hold this stock, ignore what today's file says and leave it
     alone" to the RealTest script's sizing rule -- matching the terminal exactly.
   - Run 3 (after the fix): trade count landed at 970 vs. the terminal's 964 -- a near-exact
     match. Win rate and average win/loss also came out close. This is now a genuinely
     trustworthy independent cross-check, confirmed against real data, not just a script that
     happens to run without erroring.

4. NEW -- REALTEST "ORDERS MODE" SCRIPT: built on the same now-proven logic, this asks RealTest
   "given this exact picks file, what should I buy/sell for the NEXT session?" instead of "how
   would this have performed historically?" NOT yet tested against a real RealTest run (first
   real test whenever you get to it), and has one real limitation: it only gives genuinely
   current orders if your weights export's last date is today (there's no separate "export just
   today's live picks" button yet -- see Part D, item 2).

5. THE SECTOR-SCOPING BUG -- FOUND, DIAGNOSED, AND NOW ACTUALLY FIXED (this is new since the last
   handoff):
   THE BUG: asking "Which subsector in Industrials had the highest combined anomaly score?"
   WITHOUT the words "leader page" gave you the wrong answer entirely -- it silently ignored "in
   Industrials" and returned whatever subsector scored highest across the ENTIRE universe
   (Energy, in the example you caught). You found this by comparing the same question with and
   without "leader page" and noticing they disagreed.
   THE FIX: the correct sector-matching logic already existed (built for the "leader page"
   feature) -- it just needed to be connected to ordinary questions too, not walled off behind
   one trigger phrase. This is now done, and it was built specifically so it COMBINES with other
   things you can already ask for in the same question: a reversed direction ("lowest" instead
   of "highest"), a bias condition ("improving names only"), extra requested columns, and a
   minimum group-size floor ("at least 5 members"). A new "Sector-scoped combos" tile with 5
   example questions was added to show this off.
   VERIFIED CAREFULLY: full regression suite showed 347 of 348 existing answers completely
   unchanged (the 1 difference is an already-known, unrelated flaky test), and all 7 real-browser
   test cases (the original bug, the same question with "leader page" still working, plus the 5
   new combo examples, plus one plain unscoped control question) came back correct.
   ONE THING WORTH KNOWING: one of the new example questions asks for a "5-day return" column
   alongside the usual "1D return" -- the sector-scoping is correctly applied, but the underlying
   answer engine doesn't actually add that extra column today (a separate, smaller, pre-existing
   limitation, unrelated to this fix). Flagged rather than hidden -- see Part D, item 3.
