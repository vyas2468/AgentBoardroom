PART A. WHAT SHIPPED THIS SEGMENT
----------------------------------------------------------------------------
1. TRAILING-HORIZON RETURNS FIXED (v107, live as v146):
   THE BUG: naming one subsector (e.g. "Software infrastructure") with a return question
   that used a time horizon the engine didn't recognise -- "trailing 12m return", "trailing
   30d returns", or bare "trailing returns" -- silently answered with the wrong sort: a
   plain 1-day return, or (when no return word was used at all) strength percentile. Root
   cause: the horizon-detection helper the engine's own "which stocks in this subsector..."
   path uses only understood 1/3/5/10-day and "week" phrasing -- everything longer fell
   through to a default.
   THE FIX: that helper now also recognises 30 days, 1/3/6/12 months and YTD, reusing the
   same per-symbol fields the tear sheet already computes for 1M/3M/6M/12M/YTD returns, plus
   one new field this fix adds -- an actual 30-session return (distinct from the existing
   "1 month" field, which is 21 sessions). A bare "trailing returns" with no number now
   defaults to a full trailing year. Nothing about how a horizon it already understood
   behaves has changed.
2. NEW: HIERARCHY + RETURN SPLIT DIAGNOSTIC (v107, live as v146):
   Ask things like "Hierarchy and return split for Industrials, trailing 12M return" or
   "Cluster return split for Software infrastructure, YTD" to get every Hidden Group
   (the existing cluster feature) inside that sector, ranked by mean return on your chosen
   horizon, with a positive/negative member split per group and a full per-name table
   tagged with its cluster ID, sector and return figure.
3. LEADER-PAGE LAYOUT BY DEFAULT (v108, publishing now as v147):
   You confirmed the sector-scoping fix works ("Which subsector in Industrials had the
   highest combined anomaly score?" now correctly answers Railroads), but wanted the rich,
   structured layout (matching the competitor screenshot you shared) WITHOUT needing to
   say "leader page". That's now the default for exactly this question shape -- a single
   named-sector "combined anomaly score" leader ask. A top-N list, or a different metric
   entirely, is unaffected and keeps its old plain-table answer.
4. NEW: "ANOMALY COUNT" METRIC (v108, publishing now as v147):
   Distinct from the existing "combined anomaly score" (a MEAN reading), you can now ask
   "which sector/subsector had the highest anomaly count" or "...the most anomalies" to
   rank by how many members are individually flagged anomalous, not by the group's average
   score. Renders as the same plain ranked table every other count-like metric already uses.
